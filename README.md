## Engineering Workflow

Each project will follow a practical engineering process:

1. **Understand** the problem and relevant hardware concepts.
2. **Design** the program flow and firmware structure.
3. **Implement** the solution in manageable steps.
4. **Test** the behavior in simulation or on physical hardware.
5. **Document** the results, limitations, and lessons learned.

Testing documentation will distinguish simulation results from physical hardware validation.

## Documentation Standards

As projects are developed, their documentation will aim to include:

- Problem statement and objective
- Hardware and software requirements
- Firmware architecture and implementation
- Build and execution instructions
- Test procedures and observed results
- Known limitations and possible improvements
